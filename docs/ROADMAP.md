# CodeHead — дорожная карта

План следует [R01–R16](TECHNICAL_SPEC.md); критерии определены только в ТЗ. Даты — ориентиры, выполнение подтверждается отчётами. Текущий этап — [IMPLEMENTATION_PLAN](IMPLEMENTATION_PLAN.md), QA/repair — [QA_REPORT](QA_REPORT.md), Runner — [RUNNER_REPORT](RUNNER_REPORT.md), кандидат — [CLINIC_REPORT](CLINIC_REPORT.md), worker — [WORKER_REPORT](WORKER_REPORT.md), история foundation — [STAGE_01_REPORT](STAGE_01_REPORT.md).

## Курсовая: семь сессий

Ориентир — последняя неделя ноября 2026 года, 3–4 часа на сессию. Если критерий не укладывается, фиксируется фактический остаток и пересматривается срок; замена live симуляцией не допускается.

| Сессия | Работа и проверяемый выход | UI-контрольная точка | Требования |
|---|---|---|---|
| 1. Сохраняемый процесс | Среда, контракты, PostgreSQL, Start/команды, журнал, идемпотентность, snapshot/property-тест | Собственная композиция, 10 зон/7 ролей, выбор, day/night, HTML fallback, адаптивные скриншоты | R05/R06/R08/R09, основа A07/A08/A10/A11/A15–A17 |
| 2. Worker и первые роли | Lease/fencing/recovery, provider, бюджет/trace, PM → Architect → CTO; сначала детерминированные тесты | Реальный статус роли, ожидание/ошибка/Decision, карточка источников | R03/R04/R12, A02/A06/A09/A12/A18 |
| 3. Кандидат Clinic Demo | Профиль/schema, технический шаблон, dependency cache, предложения файлов/base hash, параллельные инженеры | Просмотр требований/контракта/кода, происхождение файлов и конфликт версии, передача артефакта | R02/R07/R09, A01/A03/A11 |
| 4. QA и DevOps | Внешний HTTP suite, red/green и два неудачных repair на test provider, реальная сборка/preview | Карточка Bug/TestReport, причины блокировки, preview-состояния | R10/R11, A04/A05/A13/A14 |
| 5. Сквозное управление и визуальная связность | Привязка всех новых событий к snapshot/projection, обработка неполных/чужих событий | Движение/догоняние, роли/решения, доступность, WebGL fallback и reduced motion | R06/R13, A07/A11/A12/A15 |
| 6. Восстановление и replay | Fault injection worker/процессов, полный property-тест с артефактами/usage/Decision, экспорт | Помеченный Replay с паузой/скоростью/повтором, без побочных действий | R04/R06/R12, A09/A10/A18 |
| 7. Приёмка и материалы | Все A-критерии, отдельный ограниченный live-run, сохранение исходов/метрик, инструкция | Короткий показ записанного run и состояние ошибок; актуальная карта ограничений | R10/R15/R16, A01–A18 |

В сессиях 2–4 резервировать 60–90 минут на соответствующую интерфейсную контрольную точку и 30 минут на проверку; остаток — backend. В сессии 5 основное время отдано взаимодействиям и визуализации. Если UI-контрольная точка пропущена, это явный незакрытый результат сессии.

## Ближайший подэтап 4.3 после QA/repair

1. Использовать проверенную границу QA/repair 4.2 по QA_REPORT: настоящий standard, red→green и initial+две red подтверждены внешним suite.
2. После зелёного QA подключить отдельную DevOps-попытку к закреплённой сборке, сохранив её содержательные входы и результат.
3. Запустить preview Clinic Demo на отдельном origin с версиями и фактическим health-check; ограничения Runner/процессов остаются явными.
4. Показать сохранённые состояния preview, ошибки запуска и связь с проверенной ревизией; расширить projection/recovery проверки.
5. Реальный адаптер и live остаются отдельным этапом с согласованными provider/model/token/cost параметрами; test_injected не считается генерацией LLM.

## Риски и критерии пересмотра

| Сигнал | Действие |
|---|---|
| Нужные настройки live отсутствуют | Продолжить независимые тесты/контракты; не тратить неизвестный бюджет |
| Прикладной JSON регулярно обрывается | Применить ограничения предложений/stop_reason по R07; не принимать обрезанный результат |
| Нет визуальной контрольной точки после сессии | Завершить связанный UI до расширения набора backend-возможностей |
| GLB/риг/стилизация не проходят ранний пилот | Зафиксировать no-go и перейти к запасному стилю по R13 |
| Исполнение требует более сильного доверия | Использовать соответствующий Runner или вернуть runner_unavailable |
| Критерий сессии не достигнут | Отразить конкретную проверку и остаток; пересмотреть срок |
