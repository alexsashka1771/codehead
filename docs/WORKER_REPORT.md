# Worker и первые роли: результат этапа

24 ноября 2026 года. Проверенная реализация сессии 2 ROADMAP в явно обозначенном режиме `test`. Нормативный источник — [TECHNICAL_SPEC](TECHNICAL_SPEC.md), R03/R04/R06/R07/R12; устройство и выполненные шаги — [WORKER_DESIGN](WORKER_DESIGN.md) и [WORKER_PLAN](WORKER_PLAN.md).

## Поведение

«Запустить тест» создаёт сохраняемый run с заглушкой. Отдельный worker выполняет PM → Architect → CTO: PM сохраняет требования, Architect использует их точную версию и сохраняет архитектуру/API-контракт, CTO создаёт оценку и решение автора. Метка «ТЕСТ · заглушка» остаётся видимой; документы, попытки, входы и редактированный trace доступны в HTML, включая отсутствие WebGL.

Одобрение актуальной версии решения позволяет worker завершить уже оценённую задачу CTO под блокировкой Run, без четвёртого вызова. Устаревшая версия получает 409. Затем run явно блокируется: Backend/Frontend и создание Clinic Demo ещё не реализованы. Это результат тестовой цепочки, а не завершённое генерируемое приложение или успешный Live.

Live-провайдер отключён. Внешних LLM-запросов, платных генераций и локальных моделей в этапе нет. Нулевые токены/стоимость относятся только к тестовому источнику; неизвестные Live-расходы остаются null.

## Согласованность и управление

- Подготовка оставляет задачу queued с lease и AgentRun created; отправка переводит их в running. Провайдер работает вне транзакции. Lease, fencing token и версии входов проверяются перед отправкой и записью результата.
- Потеря lease до отправки отменяет подготовленную попытку и освобождает очередь. После отправки сохраняется uncertain и решение автора; автоматического повтора нет. Поздний результат старого worker не принимается.
- Пауза и отмена сохраняют намерение и ждут известного исхода всех операций. Retry с согласованным риском дубликата сохраняет старый uncertain и отдельное неблокирующее решение для подтверждения его отказа, не изменяющее новую попытку.
- Короткий API observer перед чтением snapshot/events/capabilities фиксирует истечение heartbeat и offline-событие при потере idle worker. Он не выполняет запросы провайдера. Снимок читается одной REPEATABLE READ транзакцией.
- Состояние и событие фиксируются вместе; seq выделяется под блокировкой Run. Snapshot и production-проекция журнала содержат непустые документы, попытки, решения и usage. Проверено их равенство с сохранением ID, версий и времени.
- Документы неизменяемы и имеют UTF-8/SHA-256, размер и происхождение. Trace содержит версии инструкций/входов, параметры, stop reason и время. Искусственные secret-canary не попадают в prompt, response, ошибки и сохранённый trace.

Независимые проверки спецификации и качества завершены. Подтверждённые замечания по конкурентному approve, recovery/deadline, управлению uncertain, heartbeat, correlation ID и редактированию credentials исправлены с RED → GREEN регрессиями.

Изменено только ожидание теста; сохранены его проверки истории, команд и итогового snapshot. После этого полный обычный набор повторно не запускался: остальные 24 сценария прошли на том же коде. Три пропущенных сценария относятся к worker и проверены отдельным прогоном с `--with-worker`.

Worker E2E подтвердил документы/хэши, snapshot == history, stale decision 409, approve без нового вызова CTO, последующую блокировку, паузу/отмену и HTML fallback. Управляющие команды во время вызова отправлялись через API, сохранённые состояния проверялись в HTML. Обычные команды через UI покрыты существующими сценариями. Компактный экран проверен: вкладка решений и кнопка одобрения доступны целиком.
