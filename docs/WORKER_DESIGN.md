# Worker и первые роли: устройство текущего этапа

24 ноября 2026 года. Это описание реализации, нормативные требования остаются в TECHNICAL_SPEC.md, R03/R04/R06/R07/R12. Автор разрешил продолжить этап 2 ROADMAP, выбрал заглушку провайдера и исключил локальные модели.

## Граница этапа

Отдельный процесс worker исполняет PM → Architect → CTO в явно обозначенном режиме `test`. Данные провайдера детерминированы, результаты имеют происхождение `test`; это проверка настоящих очереди, транзакций, решений и отображения. Live сохраняет очередь и сообщает об отсутствующем провайдере, без автоматического перехода в test. Внешних LLM-запросов и платных генераций в этом этапе нет.

После оценки CTO автор получает версионируемое решение о принятии архитектуры. Принятие не повторяет вызов CTO. Следующие роли остаются недоступны до этапа реализации Clinic Demo; успешное завершение всего run не заявляется.

## Транзакции и попытки

- Захват сериализуется блокировкой Run, lease принадлежит конкретному worker. При двух потребителях используется SKIP LOCKED. Подготовка оставляет задачу queued с lease, AgentRun created; отправка переводит их в running.
- Attempt ID, монотонный fencing token, актуальный lease и входные версии проверяются перед отправкой и принятием результата. Heartbeat продлевает lease отдельной короткой транзакцией. Работа провайдера выполняется вне транзакции.
- Истёкшая попытка до отправки отменяется и освобождает queued-задачу. После отправки её исход становится uncertain, задача и run блокируются; автоматической повторной отправки нет.
- Пауза во время вызова становится pausing до известного завершения. Отмена запоминается как запрос остановки, пока вызов не завершён; неизвестный исход не превращается в cancelled.
- Каждая мутация и полное новое представление сущностей записываются вместе. Seq выделяется под блокировкой Run. Snapshot и production-проекция включают попытки, решения и usage; старые события получают пустые новые коллекции через значения по умолчанию.
- Перед чтением snapshot/events и проверкой подключения worker API наблюдает истечение heartbeat короткой транзакцией. Потеря idle worker также создаёт сохранённое `worker.disconnected` с offline-состояниями ролей. Observer не вызывает провайдер и не исполняет длительную работу внутри HTTP; snapshot после наблюдения по-прежнему читается одной REPEATABLE READ транзакцией.

## Результаты и решения

PM создаёт требования с критериями; Architect использует точную версию требований и создаёт архитектуру/API-контракт; CTO использует их и создаёт оценку для автора. Малые текстовые артефакты сохраняются неизменно в PostgreSQL с нормализованным UTF-8 хэшем, типом, размером и происхождением. Просмотр проверяет хэш. Ответы не исполняются как код.

Decision содержит тип, открытое/закрытое состояние, версию, связанный task/attempt и варианты ответа. Resolve проверяет версию под блокировкой Run и имеет идемпотентный receipt. Принятие архитектуры переводит waiting_for_decision в queued; worker атомарно завершает уже оценённую задачу без нового вызова. Отклонение оставляет объяснимую блокировку. Для uncertain доступны подтверждение известного отказа с объяснением либо явно согласованный повтор с риском дубликата; старый uncertain сохраняется при таком повторе.

Повтор с риском закрывает исходное блокирующее решение, разрешает новую попытку и создаёт отдельное `uncertain_outcome` с `blocking=false` для старой операции. Подтверждение её отказа остаётся доступным и не меняет результат новой попытки. Такое решение не останавливает очередь, однако pause/cancel всё ещё требуют известного исхода всех операций; неизвестная старая попытка не превращается в завершённую автоматически.

## Провайдер и ограничения

Интерфейс провайдера отделён от БД. TestProvider получает описание проекта и неизменяемые входные артефакты, возвращает небольшие проверенные документы и краткое обоснование. Ограниченная задержка используется только в test для наблюдения переходов; backend-тесты запускаются без неё.

Число попыток и wall time ограничены RunLimits. Test usage показывает нулевые внешние токены/стоимость с явным именем тестового источника. Для live неизвестные значения остаются null. Заглушка live сообщает об отсутствии реализации, не возвращает тестовые документы. Trace хранит редактированные prompt/raw response, параметры, входные версии, stop reason и время; секреты удаляются до записи и перед использованием текста.

## UI и запуск

Главная фабрика сохраняет текущую графику. Test постоянно обозначается в верхней строке и истории. Карточка роли показывает реальную задачу, попытку, входы и результат; решения и документы доступны в HTML, включая клавиатуру и WebGL fallback. 3D использует существующий AgentView/Animation Controller.

Супервизор запускает worker в собственном дереве вместе с API/UI. Изолированные обычные E2E оставляют worker выключенным; сценарий worker запускается отдельным флагом. Базы разработки не очищаются. Коммиты и push не запрошены.
