# Продолжение разработки CodeHead

Прочитай AGENTS.md, README, docs/IMPLEMENTATION_PLAN.md и актуальный отчёт этапа. Нормативные требования находятся только в docs/TECHNICAL_SPEC.md (R01–R16, A01–A18, V01–V09). ROADMAP задаёт очередность, FEATURES — указатель функций, CHANGELOG — историю.

Сначала проверь фактическое состояние кода и последние результаты, не повторяя уже выполненную работу. Для изменения из нескольких шагов составь краткий план и переходи к выполнению согласованного этапа. Рутинная реализация, обратимые исправления и проверки не требуют повторного подтверждения.

Рабочая платформа — Windows, PowerShell 5.1, Node 24, Python 3.11. Используй локальный PostgreSQL, уже разрешённый пользователем, без Docker/службы. Не заменяй его SQLite; SQLite разрешена только Clinic Demo.

Продолжай текущий этап по IMPLEMENTATION_PLAN. После foundation следующая сессия — worker/lease/attempts, test provider, реальные PM/Architect/CTO и связанные UI-состояния. Главный долгосрочный приоритет — frontend; соблюдай визуальные контрольные точки ROADMAP.

Обязательные правила:

- Python владеет контрактами; генерируй TypeScript и проверяй отсутствие расхождений.
- Команды/события/снимки — R05/R06; неизвестная схема и потеря seq требуют явного восстановления.
- Модель предлагает ограниченные файлы/patch, сервер проверяет stop_reason/base_hash/права по R07.
- Никаких фиктивных live, QA, usage, preview или «активных» неподключённых ролей.
- Статус существующего тестового provider не закрывает A02. Ограниченный live выполняется отдельно по R10/R12.
- Перед исправлением бага получи воспроизведение и падающую проверку; исправляй причину.
- Перед заявлением о результате выполни подходящие проверки и сохрани фактический вывод.
- Не читай ключи из сторонних конфигураций. Не коммить/push, не удаляй данные и не выполняй внешние действия без соответствующего поручения.

Точки обязательного уточнения: отсутствующие provider/model/token/cost параметры перед платным live; изменение согласованного объёма; внешнее/разрушительное действие без разрешения. Назови конкретную причину и продолжай независимую работу. Художественный пилот имеет отдельную точку go/no-go по R13.

Отчёт этапа: работающий результат, команды/вывод проверок, ограничения и следующий конкретный шаг. Проверенную основу не называй завершённой курсовой; запланированные эксперименты не выдавай за результаты.
